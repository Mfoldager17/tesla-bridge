Your Tesla, streaming to your own server

A self-hosted replacement for Teslemetry. The car sends its data straight to you, Home Assistant gets around 80 entities, and you control the car through Tesla's official Fleet API – no middleman, no subscription.

  • Runs in Docker on a Raspberry Pi
  • MQTT or a native integration
  • One car fits in Tesla's free credit

Pick your route

Three choices decide the steps. They don't depend on each other, and the guide below follows what you pick.

  1. Check what you need

    5 minutes · reading

    • A server with Docker – a Raspberry Pi 4/5 or any x86 machine.
    • One (sub)domain, e.g. , pointing to your public IP.
    • Two (sub)domains: through your tunnel, and pointing straight to your public IP.
    • A public IP address you can forward a port on. Behind CGNAT you need a VPS or a raw TCP tunnel for port 4443.
    • A valid certificate for the name the car connects to () – and knowing which folder it's in. Nginx Proxy Manager is not required.
    • An MQTT broker that the server and Home Assistant can both reach, e.g. Mosquitto.
    • HACS in Home Assistant.
    The name must not contain the word “tesla” – Tesla rejects it. car., ev. or anything else is fine.
    Why two ports, and why it matters how you reach the internet
    PortWho connectsHow it gets in
    443 (HTTPS)Tesla fetches your public key; your browser comes back here after logina reverse proxy or a tunnel
    4443 (TCP)the car, with its own client certificatealways a port forward, straight to fleet-telemetry

    A proxy or tunnel opens the TLS connection itself, so the car's certificate would never arrive. That's why 4443 can't go through one – and why a tunnel setup needs a second, DNS-only name for the car.

  4. Run the setup script

    On the server, in a terminal

    curl -fsSL https://raw.githubusercontent.com/Mfoldager17/tesla-bridge/main/install.sh | bash

    It asks a few questions – answer with what you picked above:

    • Folder – anywhere you like. An existing install is found by itself.
    • How the internet reaches you – answer 1 (reverse proxy)2 (tunnel).
    • Client ID / Secret, VIN and a name for the car (the name becomes the entity ids).
    • MQTT – answer 1 (built-in broker)2 if it finds your Mosquitto container (it creates both users), or 3 for another broker.
    • Certificate – with Nginx Proxy Manager it's found by itself. With anything else, give it the folder (a parent folder is fine – it searches). give it the folder, or pick “get it now” and paste a Cloudflare API token with Edit zone DNS – it gets a Let's Encrypt certificate for . It is renewed weekly by itself.

    Run it again any time – to change an answer or update. Your answers are the defaults. --dry-run shows what it would do.

  6. Fill in .env

    nano .env – this is built from your choices

    Replace everything in <angle brackets>. A token: openssl rand -hex 24.

  7. Create the MQTT users

    Only with your own broker

    Replace mosquitto with your container's name, and use the password file it prints.

    # where is the password file?
docker exec mosquitto sh -c 'grep -h password_file /mosquitto/config/*.conf /etc/mosquitto/*.conf 2>/dev/null'

docker exec -it mosquitto mosquitto_passwd /mosquitto/config/passwd tesla-bridge
docker exec -it mosquitto mosquitto_passwd /mosquitto/config/passwd fleet-telemetry
docker kill -s HUP mosquitto      # re-read users, no restart

    Anonymous broker? Skip this and leave usernames and passwords empty.

  8. Put the certificate in place

    For – from wherever it lives

    SRC=<certificate folder>
mkdir -p config/fleet-telemetry/certs
sudo cp -L "$SRC"/fullchain.pem config/fleet-telemetry/certs/fullchain.pem
sudo cp -L "$SRC"/privkey.pem   config/fleet-telemetry/certs/privkey.pem
sudo chown -R $(id -u):$(id -g) config/fleet-telemetry/certs
    Made byFolder
    Nginx Proxy Manager<letsencrypt>/live/npm-<nr> – find the number with sudo grep -l <letsencrypt>/renewal/*.conf
    certbot/etc/letsencrypt/live/
    Caddy<caddy data>/caddy/certificates/<ca>/ – files are .crt and .key
    acme.sh~/.acme.sh/ – fullchain.cer and .key

    No certificate for yet? The install guide shows how to get one with certbot and Cloudflare DNS – or let the setup script do it.

    Let's Encrypt renews about every 60 days: copy again weekly with a root cron job and run docker compose restart fleet-telemetry.

  9. Start it

    docker compose up -d
docker compose logs tesla-init        # what was created, and any warnings

    Back up config/ and data/. If the app key is lost, it must be paired with the car again.

    Port 8091 only answers with the public key and the login callback – never the dashboard. Once Tesla can fetch the key, the bridge registers your domain with Tesla by itself.

  11. Forward TCP 4443 in your router

    To , port 4443. That's where the car sends its data – to :4443. Your existing services on 443 are not affected.

    Don't forward 8090. That's the dashboard, and it can unlock the car – keep it on your own network.

  12. Connect the car

    In the dashboard, on your own network

    Open http://:8090 and sign in with the token from .env (the script prints a link that signs you in). Under Setup:

    1. Sign in with Tesla.
    2. Pair the key – scan the QR code with your phone while you're at the car, and approve in the Tesla app.
    3. Wait for the car to wake – the first data arrives within a minute or two.

  13. Add it to Home Assistant

    Nothing to do: the car appears by itself under MQTT as , as long as Home Assistant uses the same broker.

    1. HACS → ⋮ → Custom repositories → https://github.com/Mfoldager17/tesla-bridge, type Integration.
    2. Install Tesla Bridge and restart Home Assistant.
    3. Settings → Devices & services → Add integration → Tesla Bridge, with URL http://:8090 and the token from .env.

    You get about 80 entities under , e.g. sensor._battery_level. All entities

  14. Optional: free commands at home

    Any time later · an ESP32 board near where the car parks

    While the car is within Bluetooth range of an ESP32, commands and wake-ups go over Bluetooth instead of the Fleet API – free, and without the internet. Away from home nothing changes.

    1. Flash an ESP32 with esphome/tesla-ble.yaml (ESPHome, ready-made).
    2. Dashboard → Settings → Bluetooth: type its address, e.g. http://192.168.1.50.
    3. Sit in the car, press Pair key and tap your key card.
